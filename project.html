What this is

A living, auto-generated map of papers Zhi Li (Allen Li) finds interesting. Each paper becomes a card with a 5-part insight that connects it back to the author's own research, critiques it, and proposes concrete ways to advance or disrupt the field.

How to add a paper

  1. Put the paper's PDF in a folder under interest/ — the folder name becomes the card's id, and the PDF can be named anything (e.g. interest/brown-ocean-effect/brown-ocean-effect.pdf).
  2. Commit and push (or upload it through the GitHub web UI).
  3. A GitHub Action reads the PDF, generates the insight, and opens a Pull Request within a few minutes.
  4. That's it — the Action commits the insight to main and the live dashboard rebuilds automatically; the new card appears under its subject tab.

That's it — drop a PDF and push. Nothing else to run; the card appears on its own.

One-time setup

See the README: add the ANTHROPIC_API_KEY secret, allow Actions to open PRs, and enable Pages.

Pipeline

push interest/<slug>/paper.pdf
   │  GitHub Action (on push to interest/**)
   ├─ extract main text + metadata (pymupdf) → interest/<slug>/paper.md
   ├─ extract one representative figure → assets/figures/<slug>/
   ├─ load research history (_data/publications.yml + published/*.md)
   ├─ Claude reads the PDF → 5-section insight JSON, grounded in your work
   └─ write _insights/<date>-<slug>.md  → commit straight to main
        ▼  GitHub Pages rebuilds automatically → new card under its subject tab

The five sections of every insight

  1. Summary & Key Contributions
  2. Connections to My Work — must name at least one real publication from _data/publications.yml (hard-checked; an ungrounded insight is rejected).
  3. Critique & Limitations
  4. Gaps & Ideas
  5. How to Advance / Disrupt the Field — concrete recommended data + methods.

Key design decisions

  • Static & Pages-native: Jekyll + only whitelisted plugins; no server, no DB.
  • Hybrid PDF reading: local text/figure extraction and native Claude PDF input, guarded by page/size and a token budget (falls back to text).
  • Idempotent: a paper is processed once (insight-absence + content-hash guard); re-pushes don't duplicate.
  • Auto-publish: the Action commits each insight directly to main and the live site refreshes — no PR/merge step (edit or revert after the fact if needed).
  • Build-safe: all model output is YAML-escaped and Liquid-neutralized so it can never break the site build.
Figure note. A representative figure may be extracted from a third-party paper and shown on its card. These are displayed under academic fair-use / scholarly-commentary for non-commercial research discussion, and every card links to the original source. To suppress a figure, delete assets/figures/<slug>/ in a follow-up commit.
